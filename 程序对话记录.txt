【V1.0 开发内容记录】

一、分类动态管理
- 创建 categories 表：支持层级分类（行业→机构/业务/资料类型）
- 后台分类管理页面：/admin/categories
  - 添加行业（顶级）
  - 添加子分类（机构/业务/资料类型）
  - 编辑/删除分类
  - 启用/禁用状态控制
- 上传页级联选择：选择行业后自动加载对应机构/业务/资料类型
- 级联API：/api/categories/tree 返回完整分类树

二、资料版本管理
- 创建 document_versions 表：独立版本记录
- 版本提交：已发布资料可提交新版本，新版本号自动递增（v2/v3...）
- 版本状态：pending待审核/published已发布/rejected已驳回/history历史
- 版本历史页面：/doc/<id>/versions 展示所有版本
- 版本详情页面：/version/<vid> 查看单个版本
- 权限控制：待审核版本仅作者和管理员可见

三、用户纠错系统
- 创建 feedback 表：记录用户反馈
- 详情页反馈按钮：有帮助/内容有误/已过时
- 反馈类型校验：内容有误和已过时必填理由
- 重复提交拦截：同一用户同类型反馈只能提交一次
- 后台反馈管理：/admin/feedback 查看和处理反馈

四、作者主页
- 公开作者页面：/author/<user_id>
- 展示：昵称、地区、加入时间、发布资料数、总浏览数、获得有帮助数
- 作者发布的资料列表（仅已发布）

五、后台管理升级
- 用户管理：/admin/users 查看所有用户，禁用/启用，调整角色
- 操作日志：所有管理操作留痕
- 四个管理模块统一导航：资料审核/分类管理/反馈管理/用户管理

【AI开发团队】
收到，进入 V1.5 阶段，接入豆包大模型实现自然语言智能搜索。

一、AI服务模块（ai_service.py）
- 封装豆包大模型API调用（火山方舟 ark.cn-beijing.volces.com）
- API Key 从环境变量 DOUBAO_API_KEY 读取，不硬编码到代码
- 模型：doubao-lite-4k（轻量版，响应快，成本低）
- 超时30秒，低温度0.3保证确定性输出
- is_ai_available() 检测服务可用性

二、自然语言意图解析
- AI模式：调用大模型从自然语言提取结构化查询条件
  （省份/城市/机构/业务/资料类型/关键词/置信度/需澄清）
- 降级模式：无API Key时自动切换规则解析
  - 省份匹配：内置省份表直接命中
  - 城市提取：省份后文本移除机构词/资料类型词后截取
  - 机构匹配：关键词直接命中（平安人寿/中国人寿/医院/银行等）
  - 资料类型：出院记录/诊断证明/发票/清单等直接命中

三、AI回答生成
- 有结果：列出匹配资料（名称/地区/机构/类型/更新时间），
  强调用户共创分享仅供参考，不编造资料内容
- 无结果：如实说明未找到，给出可能原因与建议操作，
  不伪造搜索结果
- 需澄清：信息不足时AI反问用户补充条件
- 降级回复：模板化生成，同样如实说明结果

四、接口与前端
- /api/ai/search 从501占位升级为真实可用接口
  返回：answer文字回答 + suggested_docs资料列表 +
        parsed解析条件 + has_results + need_clarify
- 首页新增 AI智能搜索框（Hero区，V1.5徽章）
  支持自然语言输入、Ctrl+Enter快捷键、结果内联展示

五、降级保障
- 无API Key/网络异常/API异常 三种情况均自动降级规则解析
- 降级解析结果标注 confidence=low
- 用户体验不因AI服务不可用而中断

一、VIP会员体系
- 新增 membership 表：user_id/days/expire_at/source(积分兑换/管理员开通)
- 会员中心 /vip：状态展示、权益说明、积分兑换开通
  （月度200积分/30天、年度2000积分/365天，未过期顺延天数）
- 积分不足拒绝兑换并引导赚积分；开通记录可查
- 会员权益（全部服务端校验）：
  1) 高级筛选：搜索页可按浏览量/更新时间排序（非VIP参数忽略）
  2) 打包下载：详情页一键下载全部图片ZIP（/doc/<id>/download）
  3) 优先审核：VIP上传资料在后台待审核列表置顶并加VIP标识
  4) 身份标识：全站昵称旁VIP徽标
- 管理端手动开通：/admin/users 每用户可开通指定天数
- API预留：/api/vip/status 查询会员状态与积分

二、广告激励
- 新增 ad_rewards 表：每日领取记录防刷
- 激励页 /ad：模拟广告位（3秒播放动效），看完自动领取+5积分
- 每日上限3次（服务端强制），第4次明确拦截
- 积分攻略面板：展示全部积分获取方式入口

三、作者付费咨询
- 新增 consultations 表：from_user提问者/to_user作者/price/status
  （pending待回答/answered已回答/refunded已退款）
- 详情页"付费咨询作者"弹窗：10积分/次，支付即扣费
- 不能咨询自己的资料；积分不足拒绝
- 作者在"我的贡献-向我咨询"中回答，提交后积分立即结算
- 未回答的咨询提问者可关闭并全额退款
- 权限：仅作者可回答(403)、仅提问者可关闭(403)
- API预留：/api/consultations 查询我的咨询列表

四、资料需求悬赏
- 新增 bounties（悬赏）+ bounty_entries（应征）两表
- 悬赏大厅 /bounty：发布悬赏（标题/地区/机构/类型/描述/积分）、
  进行中列表、我的悬赏管理、已结束列表
- 发布即冻结积分（最低10分），余额不足拒绝
- 应征：选择本人已发布资料关联（不能应征自己的悬赏、
  不能用他人资料、同一资料不能重复应征）
- 发布者采纳：积分结算给应征者，其余应征自动未采纳
- 发布者关闭（或管理员）：冻结积分全额退回
- API预留：/api/bounties 公开进行中悬赏列表

五、积分系统升级
- 新增 change_points() 支持负数消费，积分流水全程留痕
- 消费类型：vip_redeem/consult_ask/bounty_publish
- 收入类型：consult_answer/bounty_reward/ad_reward/各贡献行为

六、顺带修复（回归测试暴露的存量bug）
- document_images 增加 ref_type 列：区分主资料图片(doc)与
  版本图片(version)。此前两表主键自增序列独立，id重合时
  详情页会混入版本图片（测试十七打包下载时发现3张图=2+1混入）

【V3.0.1 修复记录】（2026-10-14）

【用户】
上传资料后，管理后台审核没有消息提示，导致无内容。
另外请检查并完善不合理内容。

【根因分析】
1. 上传表单中隐私确认 checkbox 只有 id="privacyCheck"，
   缺少 name="privacy_confirmed" 属性，导致后端
   request.form.get("privacy_confirmed") 永远返回 None，
   上传永远被服务端校验拒绝（返回400），资料未写入数据库，
   后台待审核列表自然为空。
2. 旧版数据库 document_images 表缺少 ref_type 列（V3.0新增），
   init_db 中未做 ALTER TABLE 迁移，导致上传时图片保存失败。
3. 上传第1步表单布局：一个两列 form-row 中放了3个字段
   （来源机构/省份/城市），第三个字段溢出。

【修复内容】
1. upload.html：隐私确认 checkbox 增加 name="privacy_confirmed" value="1"
2. app.py init_db：补充 document_images 表 ref_type 列的迁移
3. upload.html：重排第1步字段，每行正好两列
   （行业|用途机构 → 来源机构|省份 → 城市|区县 → 资料名称|适用业务 → 资料类型|关键词标签）
4. 列表页统一显示"用途机构"+"来源机构"：
   search.html / my.html / admin.html / index.html（含AI搜索结果）
5. 搜索关键词范围扩展到 source_org 字段（3处SQL）
6. admin.html 中"来源"字段改名为"来源说明"，避免与"来源机构"混淆
